# 2026-10-12 Q1 skills 整合與模型紀錄

## 網頁操作

```bash
bash play_skills.sh
# http://127.0.0.1:8765/web/
# 無視窗：bash play_skills.sh --headless --no-browser
```

`play_skateboard.sh` 預設也啟動同一整合版本；`Q1_LEGACY_PLAY=1` 可播放舊版本。

1. Reset 為膝蓋微彎的站立。站穩後按 **Backflip**。
2. 後翻成功後，雙腳輪＋膝輪支撐跪姿，手臂平順放下；落地模型持續平衡。
3. 一般跪姿按 **Unbox**，執行新的起立 PPO，成功後繼續由新起立 PPO 平衡。後翻落地姿態會選落地專用模型，目前仍為實驗版本。
4. 正躺／反躺先選地板姿勢，再選 Gripper 輔助或 Elbow 實驗測試。一般 Recovery 採用 Gripper 輔助版本。

Backflip / Unbox 切換只初始化控制器，不重設根節點、關節位置或速度。只有明確 Reset、正躺／反躺姿勢及獨立測試的初始樣本會寫入初始姿態。使用 Q1 URDF、CubeMars 電流／力矩限制與真實接觸；沒有 IsaacSim G1 專案的執行依賴。

## 後翻收臂微調

舊 V2 20k × 12288 的後期訓練成功率已大致持平，因此從其 final checkpoint 微調，使用 **6144 envs**、500 輪上限，而非重跑 20k。獨立驗證通過後提早停止，最後紀錄到 297 輪，選用 **model_200.pt**。

- 原本獨立測試：84/96，手臂姿態未納入成功條件。
- 收臂模型選模測試：84/96；另組未用於選模的 seeds 7107/8107/9107：**82/96**。
- 成功需完整後翻、合法接觸、連續穩定至少 2 秒，手臂最大位置誤差 <0.18 rad、最大關節速度 <0.8 rad/s。
- 選模成功樣本最大手臂誤差約 0.0524 rad（3°）；未出現前置小跳。
- 網頁在成功落地的相位繼續用同一 PPO 平衡，避免超過訓練窗口後持續推進落地參考。

權重與參考：`checkpoints/backflip_arm_rest/`。原始訓練 manifest、當時 source snapshot、可攜版 runtime hash 和訓練摘要分開保存。

## Unbox 落地姿態適應

舊 boot-kneel 4999 模型適合標準開箱跪姿；直接套用後翻的左右腿／腰角落地姿態會跌倒。`collect_landing_bank.sh` 使用新收臂後翻模型收集 **630 筆真實動態落地姿態**，只取成功、未失敗、手臂到位且低速度的狀態。

`train_unbox_transfer.sh` 從舊 boot-kneel 模型微調：先 64 envs × 30 輪檢查數值，再 6144 envs × 200 輪。訓練 reset 使用 65% 實際落地姿態、35% 標準跪姿；使用與網頁一致的接觸材質，保留高扭矩髖／腰驅動和收臂控制。標準跪姿模型 iter199 的網頁獨立驗證為 **8/8**，20 秒結束仍站穩。第一次沿用舊準備控制的落地微調仍無法從後翻落地起立，因此另做真實動態直接起立參數搜尋與短程訓練。

落地專用模型先以6144 envs × 200輪訓練，移除重新向後跪坐的準備步驟。早期測試曾得到20/32起立、13/32在18秒結束仍穩定；該程序未在初始姿態寫入後刷新IMU／運動學，僅保存為歷史紀錄。修正測試初始化後，同樣的第199輪模型為6/32起立、4/32結束仍穩定。

目前落地專用模型採膝輪連動一致的4096×120微調第119輪：**7/32起立、5/32在18秒結束仍穩定**。網頁後翻接起立的連續測試仍有跌倒；此按鈕分支明確列為實驗，不能宣稱整條流程已穩定。標準跪姿仍使用已驗證的新 transfer iter199，不會誤分到落地模型。

「Gripper 輔助」表示歷史手部接觸可用的策略，並非宣稱專門只以 gripper 接觸訓練。Elbow 與正躺 Gripper 版本可測試，完整起立未達驗收。反躺 Gripper 輔助已有成功樣本；每個按鈕的測試結果分開呈現。

每個 recovery 保存自己的 `mdp.py` 與 motor priors，避免最新控制器破壞舊 PPO；更換為重新驗證的控制器時，另保留原訓練和歷史成功版本。推論保留 IMU 延遲、6° 安裝角、編碼器偏差與訓練時相同的正規化 epsilon=0.01。`tests/test_skill_policy.py` 與 RSL-RL 模型比較的誤差為 0。

## 歷史 checkpoint

`checkpoint_inventory.json` 列出 SHA256、大小與迭代數。保留滑行、側滑、posture、Unbox、正反躺各有效／peak／final 權重，與後翻 v1/v2 20k。V1 20k 的獨立後翻成功率為 0/96，僅供歷史保存；V2 原始 20k 為 84/96，原始影片保存在 `backflip_v2_20k/`，也已上傳 https://gofile.io/d/KDTkQkgr 。中間每個 save interval 的 checkpoint 留在本機 logs，避免重複權重佔用 Git 歷史。

失敗的整合探測數據收在 `debug/`，不能當成成功驗證。新的測試數據、模型來源與影片均應一併保存，才可重現。

## 從網頁實際站立啟動

原後翻只從訓練 Reset 的初始關節／速度開始。實際站穩後的根節點速度和輪子接觸歷史不同，因此增加 `live_arm_env.py` 的訓練 reset：70% 使用從網頁實際微彎站立收集的272筆物理狀態、30% 保留原起始姿態。動作參考、收臂成功條件和馬達物理完全相同，先64×30檢查數值，再6144×200短程補訓；實際於172輪停止。第50輪獨立測試0/32成功，此版本沒有啟用，model_150.pt與來源留在 `checkpoints/backflip_live_experiment/`。不能沿用原模型84/96作為此失敗版本的成績。

網頁切換增加低速度（<0.05 m/s）、低角速度（<0.15 rad/s）的站穩閘門，避免在仍向後滑動時開始載重。參數搜尋與連續流程失敗紀錄另存；最新單機獨立測試見 `web_backflip_settled8.json`。

微彎站立使用重力和雙腳輪承重的 Jacobian 力矩補償，經真實 CubeMars 馬達作用到關節，並以輪子平衡；不施加根節點外力、不重設姿態。訓練相容的後翻參考仍採原已驗證的馬達控制。

## 膝輪連動的訓練／網頁差異

查核發現原 recovery action group 沒有 `roller_mimic`，但網頁及後翻都依 URDF 以 0.444444 倍膝角／角速度控制膝輪。直接追加 4096×150 的訓練指標雖很高，第50輪的相同落地樣本測試反而只有3/32起立、2/32結束仍穩定；此模型沒有啟用，保存在 `checkpoints/unbox_landing_continue/`。

`train_unbox_transfer.sh --web-linkage` 補上0維膝輪連動 action，並增加連續3秒站穩的獎勵。64×15小批量已確認有限數值，再以4096×120、固定學習率5e-5微調。原模型、每次短程訓練與實際網頁驗證分別保留，不能把訓練指標當成網頁成績。
